### 关键技术点 1：MuJoCo 网格顶点必须用编译后的 mesh_vert

**踩了很久的坑。** MuJoCo 编译 STL 时会把顶点**重心归零**，偏移量记在
`model.mesh_pos` 里（如 `l_hip_z_link` 的 `mesh_pos.z = -0.2229`）。
最初用「原始 STL 顶点 × geom_xmat + geom_xpos」，漏掉这一步，
结果大腿/膝盖整体下沉 22 cm，渲染出来像"腿断成两截"。

**正解**：直接用 `model.mesh_vert` / `model.mesh_face` / `model.mesh_normal`
（已是重心归零后的数据，和 MuJoCo 内部渲染逐顶点一致）建索引几何体。
附带好处：前端不再需要 STL 解析器（已删掉 js/stl.js）。

> 校验方法：`tools/dump-geoms.mjs` 列出每个 mesh 的世界 AABB，
> 在 Node 里用 mj_forward 的结果和浏览器里 `__elf.mjScene.robotGeomBounds()` 对账，
> 两边 z 范围必须逐件吻合。

其它注意：
- WASM 里 `mj_id2name(model, mjOBJ_GEOM, id)` 对未命名 geom 会返回垃圾串（如 "emsc"），
  但 `mjOBJ_MESH` / `mjOBJ_BODY` 正常，取名字时避开 GEOM。
- `mesh_face` 索引是 **0 基**，索引上限 = `mesh_vertnum - 1`。
- `mesh_facenormal` 是每面 1 条（总数 = 总三角面数），`mesh_normal` 是每顶点 1 条。

### 关键技术点 2：坐标映射与 VR 漫游

- Z-up → Y-up：`flip.rotation.x = -π/2` 再套 `yaw.rotation.y = +π/2`，
  机器人正面（MuJoCo +x）朝向 three 的 -Z，无镜像。
- VR 里相机固定在世界原点（由头显姿态驱动），**平移/旋转的是装整个 MuJoCo 世界的
  `stage` 组**，避免和 XR 头显位姿打架。参考空间 `local-floor`，
  头显里脚踩地面 = MuJoCo `z=0`。
- 进 VR 自动把机器人摆到用户正前方 2.6 m 并正对用户；左摇杆移动、右摇杆 30° 转向、
  A/X 重新正对、B/Y 世界复位。
- `stage.rotation.y = atan2(f.x, f.z)` 时机器人正对用户（f 为用户前方单位向量），已推导验证。

### 关键技术点 3：落地对齐

`qpos0[2] = 1.1` 时脚底离地 +3.7 cm。加载后按视觉网格最低点自动对齐到 `z = 0`
（`MjScene.robotMinZ()` 逐顶点算），复位与「关闭物理」都回到这个姿态。

## 任务：基于 play.py 把 elf3 的 RL 策略仿真跑起来（普通任务 + motion-tracking）

### 结论：fight_47000.pt / policy.onnx 都是 motion-tracking 策略
- actor obs=160、critic obs=277，与 mjlab `Tracking` 任务完全吻合：
  command(=motion joint_pos+joint_vel, 58) + anchor_pos_b(3) + anchor_ori_b(6)
  + base_lin_vel(3) + base_ang_vel(3) + joint_pos(29) + joint_vel(29) + actions(29) = 160
- velocity（普通 locomotion）任务的 obs 含 height_scan，维度对不上 → 项目里只有 tracking 策略，
  "普通任务"按「零动作 PD 保持」的基础链路自检实现（play.py 的 agent=zero 用法）。

### 关键突破口
1. **policy.onnx 的 metadata 存了训练参数真值**：joint_stiffness / joint_damping /
   default_joint_pos / action_scale / observation_names / anchor_body_name / body_names
   （run=2026-08-01_13-45-22）。不用猜。
2. kd/kp = 4/ω（mjlab NATURAL_FREQ=10Hz、DAMPING_RATIO=2，27/29 关节；ankle_roll 单独 0.1）。
3. action_scale = 0.25·effort/kp → effort_limit 可反推（15~150 Nm）。
4. policy.onnx **内嵌了整条 fight.npz 参考动作表**（输入 obs[1,160]+time_step[1,1]，
   输出 actions + 按 time_step Gather 的 joint_pos/joint_vel/body_pos_w/body_quat_w/...），
   与 fight.npz 逐帧零误差一致。
5. elf3.xml 的 13 个跟踪 body 世界位姿与 fight.npz **完全吻合**（max Δpos=2.4e-7 m）
   → 该 XML 就是训练/重定向所用模型；关节顺序 = 动作数据顺序。
6. MuJoCo `velocimeter`/`gyro` 传感器输出的都是**机体系**速度（实测确认）。

### 交付物
